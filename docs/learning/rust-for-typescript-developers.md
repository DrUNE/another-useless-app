# Rust для разработчика на TypeScript

Конспект на примерах из этого репозитория. Смотрите код рядом: `crates/core/src/fetcher.rs`,
`crates/core/src/ports.rs`, `crates/core-wasm/src/lib.rs`.

## Ошибки: `Result` вместо исключений

В TS функция может бросить что угодно, и сигнатура об этом молчит. В Rust ошибка — обычное
значение в типе возврата:

```rust
pub async fn save_url<H: Http, F: Fs>(...) -> Result<SaveReport, FetchError> {
    let res = http.get(url).await?;   // ошибка? сразу выходим и отдаём её вызывающему
```

- `?` — это «если `Err`, вернуть его из функции; если `Ok`, достать значение». Аналог `throw`,
  но видимый в сигнатуре и только вверх по стеку вызовов.
- `#[from]` в `FetchError` включает автоматическое преобразование `PortError` в `FetchError` при `?`.
- `unwrap()` / `expect()` при ошибке **аварийно завершают программу** (panic). В продакшен-коде их
  избегают, в тестах — нормально (`fetcher.rs`).
- `Option<T>` — вместо `T | undefined`. `ok_or_else(...)` превращает `Option` в `Result`.

## Владение: главное отличие от TS

Каждое значение в Rust имеет одного владельца. Передача «по значению» **перемещает** его:

```rust
pub async fn save_url(fs: JsFs, http: JsHttp, ...)   // забирает fs себе
```

После вызова использовать `fs` нельзя, компилятор не даст. Поэтому в тестах моста понадобилась
функция `share()`: тесту нужен тот же JS-объект и после вызова. Заимствование (`&`) даёт временный
доступ без передачи:

| Владеет | Заимствует | Аналог в TS |
|---|---|---|
| `String` | `&str` | строка, но «моя» против «посмотреть» |
| `Vec<u8>` | `&[u8]` | `Uint8Array`, но копия против вида на чужие данные |
| `T` | `&T` | параметр, который функция вправе сохранить, против того, что она только читает |

Практика: принимайте `&str` и `&[u8]`, возвращайте `String` и `Vec<u8>`.

## Похоже на TS, но иначе

| В TS | В Rust | Различие |
|---|---|---|
| `interface Fs` | `trait Fs` | Реализовать trait можно для **своего** типа, а не только объявить форму. Обобщённый код `<F: Fs>` компилируется отдельно под каждый тип (без вызова через таблицу). |
| `async` функция запускается сразу | `async fn` **ленивая** | Future ничего не делает, пока его не `await`-нут. Promise в JS стартует немедленно, future в Rust нет. |
| `x.clone()` — копия | `x.clone()` — зависит от типа | Для импортированных JS-типов в `core-wasm` вызов `fs.clone()` через авто-разыменование дал `JsValue`, а не `JsFs`, и тест не собрался. Не угадывайте тип результата, смотрите ошибку компилятора. |
| `throw` / `catch` | `Result` / `?` | См. выше. |
| `null`, `undefined` | `Option<T>` | Нельзя забыть проверить: компилятор требует обработать `None`. |
| `if (isNode)` в рантайме | `#[cfg(target_arch = "wasm32")]` | Условная компиляция: ненужный код вообще не попадает в сборку. Так тесты моста собираются только под wasm. |
| `package.json` + `bun.lock` | `Cargo.toml` + `Cargo.lock` | `--locked` — аналог `--frozen-lockfile`. |
| workspaces | `[workspace]` | Общие зависимости: `[workspace.dependencies]` — аналог `catalog`. |

## Рабочие привычки

- Читайте сообщения компилятора целиком: они подсказывают исправление (`help:`) чаще, чем кажется.
- `cargo fmt` форматирует код, CI проверяет его командой `cargo fmt --all --check`.
- Тесты лежат рядом с кодом в `#[cfg(test)] mod tests` и запускаются `cargo test`.
- Ядро проверяется на «двойниках» портов (`MemFs`, `FakeHttp`) без сети и диска. Тот же приём работает
  в `core-wasm`, где двойники написаны на JS.
