# 0011. Линтер и форматтер: oxlint и oxfmt

Статус: принято (2026-10-31)

## Контекст

`tsc` проверяет типы, но не стиль, не забытые `await`, не нарушения границ между пакетами и не типичные ошибки Solid.
Форматирование без инструмента расходится сразу (в Rust это уже случилось и потребовало отдельного коммита). Нужны
быстрые линтер и форматтер, которые работают одинаково на Linux, macOS и Windows и не требуют сложной конфигурации.

## Решение

Инструменты проекта oxc, версии закреплены в `catalog` (`oxlint`, `oxfmt`, `oxlint-tsgolint`):

- **Линтер** `oxlint --type-aware` (`bun run lint`), конфиг `.oxlintrc.json`. Категория `correctness` как ошибка плюс
  выбранные правила:
  - типовые (через `tsgolint`, совместим с TypeScript 7): `no-floating-promises`, `no-misused-promises`, `await-thenable`,
    `no-unnecessary-type-assertion`, `switch-exhaustiveness-check`, `no-explicit-any`;
  - **границы между пакетами** как правила, а не договорённость: `no-restricted-imports` в `overrides` по каталогам
    (UI не знает про Tauri и WASM, порты ни от чего не зависят, приложения не ссылаются друг на друга) и `import/no-cycle`;
  - **правила Solid** через JS-плагин `eslint-plugin-solid`: `no-destructure`, `reactivity`, `components-return-once`,
    `prefer-for` и защита от привычек React (`no-react-specific-props`, `no-react-deps`, `no-innerhtml`).
- **Форматтер** `oxfmt` (`bun run format`, проверка `bun run format:check`), конфиг `.oxfmtrc.json`: ширина 100 строк
  (как у `rustfmt`), сортировка импортов и **классов Tailwind** по стилям проекта (`stylesheet` указывает на `theme.css`,
  поэтому кастомные токены вроде `bg-surface` распознаются). Rust форматируется `cargo fmt`; `bun run format` запускает оба.
- **Исключено из проверок:** сгенерированный `apps/native/src/bindings.ts` (иначе тест на актуальность привязок упадёт,
  [ADR-0009](0009-typed-ipc-tauri-specta.md)), `packages/core-wasm/pkg`, иконки, lock-файлы и markdown. Прозу и широкие
  таблицы документов форматтер превратил бы в шумные диффы.
- **Не включены:** плагин `react` (правила хуков и свойств React неприменимы к Solid) и правило `solid/imports`
  (написано под Solid 1.x и переписало бы импорты в устаревшие пути).

## Альтернативы

- **ESLint + typescript-eslint + eslint-plugin-solid + Prettier.** Самая зрелая связка с огромной экосистемой правил, но
  несколько пакетов, сложная конфигурация и в десятки раз медленнее: здесь `oxlint` проверяет весь репозиторий с типами
  за 0,4 с, а `oxfmt` форматирует за 0,5 с.
- **Biome.** Один инструмент для линта и форматирования и тоже быстрый, но плагинов для Solid нет, а правила на типах
  у него слабее.
- **dprint.** Только форматтер, без сортировки классов Tailwind «из коробки».
- **Линтер без правил Solid** (только `tsc` и предупреждения Solid в dev-режиме). Деструктуризация props и чтение сигнала
  вне отслеживаемой области компилируются без ошибок и вылезают только при запуске.

## Последствия

- (+) Весь цикл проверки укладывается в доли секунды, поэтому его можно запускать на каждое сохранение и в CI.
- (+) При внедрении инструменты сразу нашли два реальных замечания: лишнее приведение типа в `requirePort` и асинхронный
  обработчик формы, переданный туда, где ожидается `void`.
- (+) Правила Solid ловят то, чего не видит `tsc`, и подсвечивают привычки из React (`className`, `htmlFor`,
  массив зависимостей в `createEffect`). Они проверены на корректном коде Solid 2 из официальной шпаргалки: ложных срабатываний нет.
- (+) Границы ADR-0006 теперь проверяются автоматически (для TS-кода). Rust-зависимости ядра по-прежнему проверяются
  только сборкой под wasm32, остальное в #6.
- (−) **Версии молодые:** `oxfmt` 0.x, JS-плагины `oxlint` экспериментальные, `eslint-plugin-solid` написан под Solid 1.x.
  Поэтому версии закреплены, а набор правил Solid ограничен проверенными.
- (−) Для JS-плагинов `oxlint` нужен Node.js в `PATH` (в CI он есть, на Windows и macOS его придётся поставить).
- (−) Шаблоны в `no-restricted-imports` в стиле gitignore: `*` не пересекает `/`, поэтому нужны `**`. Первая версия правил молча
  пропускала три из пяти нарушений, их нашла проверка мутациями (намеренное нарушение должно приводить к ошибке).
  Добавляя границу, проверяйте её таким же образом.
- (−) Два форматтера (`oxfmt` для TS, `cargo fmt` для Rust) и два набора правил, а не один инструмент.
- (−) Правила на типах требуют работающего `tsconfig` в каждом пакете и привязаны к версии `tsgolint`, которая следует за TypeScript.
