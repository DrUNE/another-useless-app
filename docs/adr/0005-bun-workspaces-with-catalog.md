# 0005. bun workspaces с `catalog`, без Turborepo

Статус: принято (2026-10-31)

## Контекст

Монорепозиторий содержит несколько JS/TS-пакетов (`packages/*`, позже `apps/*`) и Rust-крейты.
Нужен менеджер пакетов с workspaces и способ держать версии зависимостей согласованными.
Изначально рассматривался pnpm + Turborepo.

## Решение

- **bun** как менеджер пакетов и раннер скриптов (`bun install`, `bun run --filter`).
- **bun workspaces**: `workspaces.packages` в корневом `package.json`.
- **`catalog`**: все общие версии (solid-js, vite, typescript, tailwind, tauri) заданы в одном месте,
  в пакетах указывается `"catalog:"`.
- **Turborepo не используем** на этом этапе. Rust собирается своим инструментом (`cargo`), которому
  кэширование и граф зависимостей уже встроены. Для JS-части пакетов мало, `bun run --filter` хватает.
- Для Rust-части — отдельный `Cargo.toml` с `[workspace]` и `[workspace.dependencies]`.

## Альтернативы

- **pnpm + Turborepo.** Зрелый и самый распространённый вариант, строгая изоляция
  зависимостей, кэш задач между пакетами и CI. Отклонено на данный момент: больше инструментов
  при малом числе пакетов, а bun даёт и установку, и запуск скриптов, и catalog.
- **npm/yarn workspaces.** Нет `catalog` (в yarn есть похожий механизм), медленнее.
- **Nx.** Мощнее, но тяжелее и избыточен для проекта такого размера.

## Последствия

- (+) Один инструмент для установки и запуска, быстрая установка.
- (+) Версии в одном месте, нет расхождений между пакетами.
- (+) Меньше конфигурации.
- (−) bun моложе pnpm: возможны нюансы совместимости с инструментами экосистемы (Tauri CLI,
  vite-плагины). **Не проверено**: `@tauri-apps/cli` и `vite-plugin-solid` под bun проверим на шагах 2 и 4.
- (−) Нет кэша задач между пакетами. Когда сборки замедлятся, вернёмся к Turborepo (он
  поддерживает bun) отдельным ADR.
- (−) Часть CI-инструментов по умолчанию ожидает npm/pnpm: установку bun придётся добавлять явно.
