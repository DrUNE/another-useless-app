# 0012. Воспроизводимое окружение: закреплённые версии, doctor и devcontainer

Статус: принято (2026-10-31). Часть про Node.js в образе и в `doctor` заменена
[ADR-0013](0013-wasm-boundary-tests-in-typescript.md).

## Контекст

Проект собирается на нескольких тулчейнах (Rust, bun, `wasm-bindgen-cli`, системные библиотеки Tauri), и у него несколько
целей. На практике инструменты не оказывались на месте или имели не ту версию: не было таргета wasm32, версия `wasm-bindgen-cli`
должна совпадать с крейтом, список системных пакетов приходилось дополнять по одному, а в трёх местах (README, CI, позже образ)
он дублировался. Нужно, чтобы проект открывался и собирался на чужой машине (Linux, macOS, Windows). Менеджер пакетов и среда
скриптов — bun, чтобы не зависеть от связки Node.js и pnpm ([ADR-0005](0005-bun-workspaces-with-catalog.md)).

## Решение

Три слоя, от самого лёгкого к самому тяжёлому. Каждый полезен без следующего.

**1. Одна версия в одном файле репозитория; все остальные читают её оттуда.**

| Что | Источник | Кто читает |
|---|---|---|
| Rust (точная версия), таргет wasm32, компоненты | `rust-toolchain.toml` | rustup локально, CI, контейнер, `doctor` |
| bun | `package.json` → `packageManager` | CI (`bun-version-file`), `doctor` |
| `wasm-bindgen-cli` | `Cargo.lock` (версия крейта) | CI, контейнер, `doctor` |
| Системные пакеты Debian/Ubuntu | `tools/system-deps/debian.txt` | CI, контейнер, `doctor` |

Одна команда `rustup toolchain install` ставит Rust, таргет и компоненты из файла. Версия Rust закреплена точной (`1.99.1`),
а не плавающим `stable`: иначе результат зависит от дня запуска. Обновляется осознанным изменением файла.

**2. `bun run doctor`** (`tools/doctor`, TypeScript, покрыт тестами) проверяет окружение по группам `core`, `wasm`, `native` и
печатает, что поставить для вашей ОС. Он **только читает**: `RUSTUP_AUTO_INSTALL=0` не даёт `rustup` скачивать тулчейны
по ходу диагностики (без этого проверка «установлен ли Rust» всегда проходила бы). Для Debian/Ubuntu и ALT он печатает точную
команду, для других дистрибутивов, Windows и macOS ссылается на документацию Tauri, а не угадывает пакеты.

**3. Devcontainer** (`.devcontainer/`): Debian bookworm со всем нужным. `bun` и `rustup` копируются из **официальных образов с
закреплённым тегом**, а `wasm-bindgen-cli` собирается из исходников (`cargo install --locked`). Готовые бинарники из интернета
не скачиваются и не запускаются, `curl | sh` не используется, поэтому образ собирается на любой архитектуре без списка бинарников.
`target`, `node_modules` и кэш cargo лежат в томах контейнера: на Windows и macOS доступ к смонтированным каталогам медленный.

**Node.js.** Менеджер пакетов, скрипты, сборка, линтер, тесты (`vitest`) работают на bun, и контейнер это подтверждает. Единственное
исключение: `wasm-bindgen-test-runner` (`bun run test:wasm`) запускает тесты через настоящий Node.js и **не работает на шиме
`node`, который подставляет bun** (`ReferenceError: document is not defined`). Поэтому в образ копируется один бинарник `node`
из официального образа, а `doctor` предупреждает, если его нет (предупреждение, а не ошибка: он нужен не всем).

## Альтернативы

- **Только devcontainer.** Не решает окно Tauri, сборки под Windows и macOS, эмулятор Android и iOS. Нужен и без контейнера вариант.
- **Nix.** Даёт лучшую воспроизводимость, но не работает на Windows без WSL и заметно сложнее в освоении.
- **mise / asdf.** Закрепляют bun и Node, но не Rust-компоненты и не системные библиотеки.
- **Скачивать готовые бинарники в образ.** Быстрее собирается, но означает запуск скачанного кода, отдельный список под каждую
  архитектуру и ещё одну версию для синхронизации. Выбрана сборка из исходников и официальные образы.
- **Запускать wasm-тесты в браузере вместо Node.** Убирает Node, но требует браузер и драйвер: тяжелее. Альтернатива: тестировать
  мост через `vitest` на bun, как есть на всей остальной части. Отложено, это перепишет тесты.
- **Использовать этот же образ в CI.** Убрало бы остаток дублирования, но заменит быстрые готовые раннеры сборкой образа на 3,7 ГБ.

## Последствия

- (+) Недостающий таргет или не та версия Rust больше не загадка: один файл и одна команда; `doctor` называет причину.
- (+) Список системных пакетов и версии больше не дублируются: тест (`consistency.test.ts`) ловит расхождение версии bun в
  `package.json` и контейнере, а также возврат жёстко прописанных версий в CI.
- (+) Контейнер проверен целиком: 13 шагов (установка, `doctor`, typecheck, lint, format, тесты vitest, `cargo test`, WASM сборка и тесты,
  сборка web, тесты Tauri, релизная сборка Tauri без упаковки) проходят в нём, а `node` в начальной версии образа отсутствовал,
  что и показало зависимость `test:wasm`.
- (−) **Образ большой:** 3,72 ГБ, первая сборка около 7 минут (компиляция `wasm-bindgen-cli` примерно 4). Повторные быстрее за счёт кэша слоёв.
- (−) **Версия bun записана дважды** (`packageManager` и аргумент сборки `devcontainer.json`): `FROM` не может читать `package.json`.
  Расхождение ловит тест. Версия Node в образе закреплена только мажорной (`24`).
- (−) Контейнер не заменяет хост: окно Tauri, сборки под Windows и macOS (для них CI-матрица, #6), Android-эмулятор (нужен KVM) и iOS остаются
  на хосте. На Windows и macOS нужны Docker Desktop или WSL2.
- (−) `doctor` для Windows не реализован (честно сообщает `skip`), для macOS проверяет только Xcode Command Line Tools; подсказки для
  дистрибутивов, кроме Debian-семейства и ALT, ссылаются на документацию.
- Не проверено: сборка образа и работа под `linux/arm64` (Mac на Apple Silicon): образы-источники многоархитектурные, а сам образ
  здесь не собирался; запуск в VS Code, Codespaces и на Docker (проверено на Podman без root); Windows и macOS как хосты.
