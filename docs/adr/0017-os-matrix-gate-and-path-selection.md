# 0017. CI: матрица ОС, один итоговый check и выбор jobs по путям

Статус: принято (2026-10-31). Заменяет перечень обязательных проверок из [ADR-0007](0007-protect-main-squash-only.md): вместо четырёх имён jobs обязательна одна проверка `ci`.

## Контекст

Проект кроссплатформенный, а CI работал только на Linux. Всё, что зависит от ОС (переводы строк, пути, встраивание ресурсов, оболочка, платформенные сборки Tauri), не проверялось. К тому же:

- чем больше jobs и ОС, тем дольше и дороже каждый PR, а правка документации не должна запускать сборку Tauri на Windows;
- обязательные проверки в защите ветки заданы **именами** jobs ([ADR-0007](0007-protect-main-squash-only.md)): каждое добавление ОС или job потребовало бы правки настроек репозитория;
- задачи, пропущенные по условию, в матрице выглядят в списке проверок под неразвёрнутым именем, и обязательная проверка по старому имени «зависает» в ожидании.

## Решение

1. **Матрица ОС** (`ubuntu-latest`, `macos-latest`, `windows-latest`) для `rust`, `ts` и `native` (десктоп). Job `wasm` остаётся на Linux: ему нужны `wasm-bindgen-cli` и Chrome. У ubuntu-вариантов прежние имена,
   у остальных суффикс `[macos-latest]` или `[windows-latest]`. `fail-fast: false`: нужны результаты всех ОС, а не первая ошибка.
2. **Выбор jobs по изменённым файлам** функцией с тестами (`tools/ci`, 11 тестов), а не набором шаблонов в YAML. Job `changes` вычисляет, что нужно: для `pull_request` по `git diff HEAD^1 HEAD` на merge-коммите (так видно ровно то,
   что приносит PR), вне PR запускается всё. Для каждого job задан список файлов, которые на него **заведомо не влияют**; всё остальное, включая неизвестное, считается влияющим. Ошибка в списке даёт лишний запуск, а не пропущенную проверку.
   Проверено на настоящей истории git: PR только с документацией пропускает все четыре job, правка Rust запускает `rust`, `wasm`, `native` и пропускает `ts`.
3. **Один итоговый check `ci`** (`needs` всех jobs, `if: always()`): пропущенные jobs считаются успехом, упавшие и отменённые ломают его. Именно `ci` должна быть единственной обязательной проверкой: тогда матрица
   и список jobs меняются без правки защиты ветки, а пропуск по путям не оставляет проверку в ожидании.
4. **`.gitattributes`** закрепляет LF (`* text=auto eol=lf`), иначе git на Windows подменяет переводы строк на CRLF, и форматтеры считают код неотформатированным.

## Что нашла матрица

Первый прогон на трёх ОС показал, что Rust и TS проходят везде, а сборка Tauri нет. Обе ошибки найдены только благодаря матрице:

- **macOS:** `symbol _EMBED_INFO_PLIST is already defined`. `tauri::generate_context!()` на macOS встраивает `Info.plist` символом, а в тестовой сборке макрос раскрывался дважды (в `run()` и в тестах). Теперь он раскрывается один раз
  в вспомогательной функции.
- **Windows:** тестовый exe не запускался (`STATUS_ENTRYPOINT_NOT_FOUND`, `0xc0000139`). `tauri-build` встраивает манифест с Common Controls v6 только в бинарники, а тесты библиотеки собираются отдельным exe без него,
  и загрузчик берёт старую `comctl32`. Первое исправление через `rustc-link-arg-tests` не сработало: Cargo принимает эту директиву только для интеграционных тестов из `tests/` («package does not have a test target»).
  Рабочее решение: отключить манифест у `tauri-build` на Windows и встроить тот же манифест во все цели пакета (`embed_resource::compile_for_everything`).

Часть правок сделана заранее по чтению кода и не доказана CI: `fileURLToPath` вместо `URL.pathname` в тесте (на Windows `pathname` даёт `/D:/…`) и адрес источника IPC-запроса `http://tauri.localhost` на Windows, как в документации `tauri::test`.

## Альтернативы

- **Фильтры `paths:` на уровне workflow.** Простейший способ пропустить работу, но обязательная проверка в таком случае вообще не создаётся и PR навсегда «ждёт». Известная ловушка; итоговый `ci` её обходит.
- **Готовое действие `dorny/paths-filter`.** Работает, но добавляет стороннюю зависимость и оставляет логику выбора в YAML без тестов.
- **Перечислить все имена в защите ветки.** Каждое изменение матрицы требует ручной правки настроек.
- **Матрица только для десктопа.** Дешевле, но Rust, TS и форматирование на Windows тогда не проверялись бы, а именно там живут расхождения вроде переводов строк.
- **Не пропускать ничего.** Проще, но Windows-сборка Tauri занимает около 6 минут на каждый PR, включая правку опечатки.

## Последствия

- (+) Проект проверяется на ОС, для которых он создаётся. Время первого прогона: `rust` 19 с (Linux), 30 с (macOS), 60 с (Windows); `ts` 14, 19 и 32 с; `native` 1 мин 35 с, 56 с и 6 мин (Windows, холодный кэш).
- (+) Матрица и список jobs меняются без правки защиты ветки; пропуск по путям не зависает.
- (+) Красный job на любой ОС ломает `ci` (проверено: пока Windows был красным, `ci` падал).
- (−) **Списки «заведомо нерелевантных» файлов нужно поддерживать вручную.** Безопасный по умолчанию режим защищает от пропуска, но не от лишних запусков; новый каталог без записи запустит всё.
- (−) Нужно один раз обновить защиту ветки: заменить четыре имени на `ci`. До этого PR, пропускающий job по путям, будет ждать старое имя.
- (−) `macos-latest` сейчас на архитектуре arm64; Intel macOS не проверяется. Windows ARM тоже.
- (−) Windows и macOS не входят в `wasm` (там `wasm-bindgen-cli`, Chrome и e2e): сквозной сценарий идёт только на Linux.
- (−) В списке проверок пропущенные матричные jobs показываются под неразвёрнутым именем (`rust (cargo test) [${{ matrix.os }}]`); это косметика, а решение принимает `ci`.
- (−) Windows-сборка Tauri самая медленная и дорогая часть CI. Кэш `rust-cache` сокращает её, но не до уровня Linux.
