# 0019. Лицензии: MIT для кода, CC BY 4.0 для документации

Статус: принято (2026-11-01). Закрывает пробел, отмеченный в [ADR-0018](0018-dependency-supply-chain-checks.md).

## Контекст

Репозиторий публичный, но лицензии в нём не было. Без неё по умолчанию все права защищены: код можно смотреть, но нельзя использовать, изменять и распространять. Проект учебный, и его ценность в том, чтобы им можно было пользоваться и учиться по нему.
В репозитории два вида содержимого: исходный код и тексты (ADR и конспекты в `docs/`). Автор выбрал MIT и Creative Commons.

Creative Commons сами не рекомендуют применять свои лицензии к программам (FAQ: «We recommend against using Creative Commons licenses for software»). Причины: в CC-лицензиях нет условий о распространении исходного кода и о патентах, и они
несовместимы с основными лицензиями ПО. Тот же FAQ допускает CC для документации, а CC0 называет приемлемой для программ.

## Решение

- **Код** (`crates/`, `packages/`, `apps/`, `tools/`, `tests/`, а также корневые README и AGENTS.md) под **MIT**: файл `LICENSE` построен из эталонного текста SPDX с подстановкой «Copyright (c) 2026 Andrey Litvinov».
- **Тексты** в `docs/` под **CC BY 4.0**: `docs/LICENSE` содержит официальный текст лицензии без изменений и пояснение сверху. Использование и изменение разрешены при указании авторства. Фрагменты кода внутри текстов остаются под MIT.
- Лицензия заявлена в манифестах: `[workspace.package] license = "MIT"` и `license.workspace = true` у каждого крейта, `"license": "MIT"` в корневом `package.json`.
- `cargo-deny` проверяет лицензии наших крейтов наравне с чужими (`[licenses.private] ignore = false`): новый крейт без лицензии не пройдёт.
- Тест согласованности следит за лицензиями (наличие файлов, имя и год, поле во всех манифестах, официальный текст CC).

## Альтернативы

- **MIT OR Apache-2.0** (двойная лицензия, обычная для экосистемы Rust). Apache-2.0 добавляет явный патентный грант. Для учебного проекта без патентных рисков это лишнее усложнение, автор выбрал одну MIT.
- **CC для всего, включая код.** Прямо не рекомендовано самими CC по причинам выше.
- **CC0 или Unlicense/0BSD для кода.** Отказ от почти всех условий, в том числе от требования сохранять уведомление об авторстве. Автор выбрал MIT, где оно сохраняется.
- **CC BY-SA 4.0 для текстов.** Требует распространять производные под той же лицензией. Строже, чем нужно для учебных материалов.
- **CC BY-NC (запрет коммерческого использования).** Не является свободной лицензией и ограничивает обычное использование материалов.
- **Копилефт для кода (MPL-2.0, GPL, AGPL).** Требует открывать изменения, но заметно сужает возможности использования. Нам это не нужно.

## Последствия

- (+) Код и тексты можно использовать и изменять; GitHub определяет лицензию репозитория.
- (+) Зависимости выбор не ограничивают: в графе Rust только разрешительные лицензии и MPL-2.0 (файловый копилефт), это проверяет `cargo-deny`.
- (−) У MIT нет явного патентного гранта (он есть у Apache-2.0).
- (−) **Обязанности при выпуске бинарников:** лицензии MIT, Apache и BSD зависимостей требуют сохранять их уведомления в поставляемой программе. Сейчас это не автоматизировано (список лицензий зависимостей нужно будет генерировать перед первым релизом).
- (−) Лицензии JS-зависимостей не проверяются автоматически (нет инструмента, как `cargo-deny` для Rust).
- (−) Вклад сторонних участников явно не оформлен (нет CLA или DCO): действует правило GitHub о том, что вклад в репозиторий с лицензией распространяется на тех же условиях.
- (−) Год в уведомлении нужно обновлять при существенных изменениях по усмотрению автора.
- Это не юридическая консультация: для коммерческого распространения стоит свериться со специалистом.
