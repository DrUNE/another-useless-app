# 0010. Нативное приложение: изоляция сборки и модель доверия

Статус: принято (2026-10-31). Дополняет [ADR-0006](0006-independent-builds.md) и [ADR-0007](0007-protect-main-squash-only.md).

## Контекст

Tauri собирается только с системными библиотеками (на Linux: WebKitGTK, GTK 3, libsoup 3, D-Bus, libxdo и др.).
Остальные цели (CLI, WASM) их не требуют. Кроме того, интерфейс в WebView — это веб-страница, которой нельзя
доверять так же, как Rust-коду: если в неё попадёт чужой скрипт (XSS, сторонняя зависимость), он получит всё, что
доступно странице через IPC.

## Решение

**Изоляция сборки.** Крейт `app-native` лежит в общем Cargo workspace (один `Cargo.lock`, общие
`[workspace.dependencies]`, `cargo fmt` видит весь код), но исключён из базовых проверок:

- job `rust` в CI: `cargo test --workspace --exclude app-native`, локально `bun run test:rust`;
- отдельный job `native (desktop build)` ставит системные пакеты, запускает `cargo test -p app-native`
  и `bun run build:native -- --no-bundle`.

**Минимум полномочий.**

1. *Команды требуют явного разрешения.* В `build.rs` команды объявлены в манифесте приложения
   (`AppManifest::commands`), поэтому каждая доступна интерфейсу только при наличии `allow-<имя>` в capabilities.
   Без этого любая зарегистрированная команда была бы доступна из JS по умолчанию.
2. *Capabilities разделены по платформам:* `capabilities/desktop.json` и `capabilities/mobile.json`
   (`platforms`), хотя сейчас они совпадают. Мобильные платформы получат свои ограничения (#7).
3. *Системные плагины не подключены.* Файлы и сеть доступны только через команды приложения, которые вызывают
   общий код ядра на Rust, а не через `@tauri-apps/plugin-fs` и `plugin-http` из JS.
4. *Путь из интерфейса — недоверенный ввод.* Команда принимает только относительные пути без `..` и пишет
   внутрь каталога данных приложения (`resolve()` в `commands.rs`). Это нативный аналог песочницы OPFS в вебе.
5. *CSP задан явно* (`default-src 'self'`, `connect-src ipc: http://ipc.localhost`), а не отключён (`null`).

## Альтернативы

- **Отдельный Cargo workspace для `src-tauri`** (как делает `tauri init`). Полная изоляция, но второй `Cargo.lock`
  и две версии одних и тех же зависимостей ядра. Исключение из проверок даёт ту же независимость без дублирования.
- **Включить `app-native` в базовые проверки и ставить WebKit везде.** Каждый запуск `cargo test --workspace`,
  в том числе у разработчика CLI, требовал бы системных библиотек.
- **Права по умолчанию (все команды доступны).** Короче в настройке, но любая новая команда сразу открыта странице.
- **Плагины `fs`/`http` и порты на TS.** Подразумевало бы вторую реализацию портов на TS ради Tauri и ушло от общего
  Rust-кода, ради которого выбрано Rust-ядро ([ADR-0002](0002-rust-core-wasm-for-web.md)). Область доступа плагинов
  пришлось бы описывать отдельно.

## Последствия

- (+) Разработчик CLI и WASM не ставит WebKit; CI этих целей быстрый.
- (+) Забытое разрешение сразу видно: IPC-тесты падают с `save_url not allowed. Permissions associated with this
  command: allow-save-url` (проверено удалением разрешения).
- (+) Скомпрометированный интерфейс не может записать файл за пределами каталога данных и не получает системных
  плагинов.
- (−) Новая команда требует трёх согласованных правок: Rust-функция, строка в `build.rs`, разрешение в обеих
  capabilities. Тесты IPC ловят пропуск, но только если для команды есть тест.
- (−) `cargo test --workspace` без `--exclude app-native` на машине без WebKit падает. Об этом сказано в README и AGENTS.md.
- (−) Символические ссылки внутри каталога данных не проверяются, значит, ссылка, созданная другим процессом, могла
  бы вывести запись за его пределы.
- (−) Список обязательных проверок защиты `main` (ADR-0007) нужно дополнить `native (desktop build)`.
- Не проверено: CSP и разрешения в настоящем окне WebKit. Тесты идут через тестовую среду Tauri (`MockRuntime`)
  и headless Chromium, а настоящее окно не открывалось.
