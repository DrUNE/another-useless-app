# 0014. Граница UI и ядра: единый интерфейс Core, типизированные ошибки и контракт как данные

Статус: принято (2026-10-31). Применяет подход [ADR-0003](0003-ports-and-adapters.md) к границе между UI и ядром и использует
решения [ADR-0008](0008-wasm-boundary.md) (WASM) и [ADR-0009](0009-typed-ipc-tauri-specta.md) (IPC).

## Контекст

Одно и то же ядро вызывается двумя способами: в браузере через WASM, в Tauri через IPC. Интерфейс (Solid) должен быть один и не знать, где
исполняется ядро. До этой задачи так не было:

- интерфейс владел типом `FetcherService`, а в `core-wasm` лежал похожий `Core`: два описания одного и того же;
- ошибки IPC были типизированы (`CommandError`), а ошибки WASM приходили строками вида `io: …`;
- правило допустимости пути («относительный, без `..`») жило только в Tauri; в вебе его заменяла проверка адаптера OPFS;
- ядро передавалось пропсом, веб работал на заглушке.

## Решение

1. **Один контракт** в пакете `@app/core-api`: интерфейс `Core`, `SaveReport`, причина отказа `CoreError` (размеченное объединение по `kind`),
   исключение `CoreException` (`Error` со стеком и типизированным полем `error`) и проверка формы `isCoreError`. Пакет ни от чего не зависит
   (правило линтера), а интерфейс и все реализации зависят от него.
2. **Типизированные ошибки везде.** Tauri присылает `CommandError`, форма которого проверяется компилятором (`toCoreError` в `apps/native/src/core.ts`).
   WASM-привязка отклоняет промис обычным объектом `WasmError` (форма описана в Rust, попадает в `.d.ts`), а `createCore` превращает его в
   `CoreException`. Всё нетипизированное (паника, сбой загрузки модуля) пробрасывается как есть: это не отказ контракта.
3. **Политика путей в общем ядре**: `app_core::path::validate_relative`. Её вызывают оба недоверенных входа (команда Tauri и экспорт WASM), корень данных выбирает
   платформа (каталог данных приложения, песочница OPFS). CLI как доверенный вызывающий её не применяет.
4. **Ядро приходит через контекст Solid** (`CoreContext`). Точка входа создаёт реализацию (`createCore(createWebPlatform())` или `createIpcCore()`) и
   оборачивает ею `<App>`. Пакет `@app/app` знает только `@app/core-api`; это закреплено правилами линтера.
5. **Контракт как данные**: `packages/core-api/contract/scenarios.json` (8 сценариев: успех, подсчёт байтов, статус, три вида недопустимого пути, сбой запроса,
   сбой записи). Его читают: TS-тесты настоящего WASM-ядра с портами в памяти (`defineCoreContract`), Rust-тест IPC Tauri
   (`ipc_follows_the_shared_core_contract`) и TS-тест адаптера IPC (как ответ превращается в `CoreException`). Если WASM и Tauri расходятся для
   одного и того же сценария, падает минимум один из двух тестов.
6. **Сборка web теперь зависит от WASM**: `dev`, `build` и `check` собирают модуль сами; типы web проверяет job `wasm`, а не `ts`; сборка web
   перенесена в тот же job.

## Альтернативы

- **Интерфейс остаётся в `@app/app`.** Зависимости пошли бы «реализация → UI», а не наоборот: ядро не должно знать про интерфейс.
- **Ошибки строками и разбор префиксов** (`io: …`). Хрупко: текст платформы меняется, а `kind` нет.
- **Передавать ядро пропсом.** Работает для одного компонента, но тащит зависимость через всё дерево; контекст масштабируется без изменения промежуточных компонентов.
- **Один общий TS-набор контрактных тестов с двумя «харнесами».** IPC нельзя запустить в vitest без Rust; тест, где Rust подменён моком на TS, проверял бы сам мок.
  Данные, которые читают обе стороны, избавляют от этого.
- **Генерировать `CoreError` из Rust для обеих реализаций.** `specta` описывает только IPC; для WASM пришлось бы вводить второй генератор. Пока форма описана
  тремя местами (`CommandError`, `to_js_error`, `CoreError`), и для WASM её стережёт контрактный тест, а не компилятор.

## Последствия

- (+) UI один, реализация подменяется в точке входа; в вебе и в Tauri работает один и тот же код интерфейса и один тип ошибки.
- (+) Недоверенный путь отвергается одним и тем же кодом в обоих входах. Это проверено мутацией: если убрать проверку `..` в ядре, падают и WASM-тесты, и IPC-тест.
- (+) Контракт проверяется на обеих настоящих реализациях; кроме того, при внедрении нашлась и исправлена ловушка тестов (`beforeEach` с возвращаемым значением).
- (−) Форма ошибки описана трижды (две в Rust, одна в TS). Для IPC расхождение ловит компилятор, для WASM только тесты контракта.
- (−) Контракт сравнивает по `kind` и точным полям; тексты `io` и `network` у платформ разные (ОС, `fetch`) и намеренно не сверяются.
- (−) Проверка «до сети не дошли» (`httpContacted`) возможна только в WASM-тестах; в Tauri о том, что запрос не уходил, говорит вид ошибки (`invalidPath`, а не `network`).
- (−) Web требует Rust даже для `dev` и `check` (следствие ADR-0008); job `ts` больше не проверяет типы web, это делает `wasm`.
- (−) Сценарии лежат в JSON без схемы; их согласованность проверяет тест в `core-api`.
- Не проверено: окно Tauri с IPC-ядром в настоящем WebView (проверены IPC-слой в тестовой среде и сборка), Safari и Firefox. Сквозной сценарий веб-приложения прогнан
  вручную в Chromium (WASM, OPFS, `fetch`, ошибки на экране) и в CI пока не входит (#6).
