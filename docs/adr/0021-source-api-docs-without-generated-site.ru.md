# 0021. API-документация в исходниках без генерируемого сайта

Статус: принято (2026-11-02)

[English version](0021-source-api-docs-without-generated-site.md)

Заменяет [ADR-0020](0020-bilingual-docs-and-api-reference.ru.md).

## Контекст

ADR-0020 добавило сайт TypeDoc/Rustdoc и GitHub Pages вместе с двуязычной исходной документацией.
Сайт требует отдельной версии TypeScript, настройки generated output, системных зависимостей CI и
отдельной публикации. Он дублирует возможности package-экосистем и редакторов, хотя репозиторий пока
не публикует crates и npm-пакеты.

## Решение

1. **Языковая политика исходников сохраняется.** Английский Markdown каноничен, русские версии имеют
   суффикс `.ru.md`, обычные `//` комментарии остаются русскими, новые Rustdoc/TSDoc — английскими.
   Тест языковых пар и постепенная миграция не меняются.
2. **Отдельного API-сайта нет.** Удаляются команды `docs`, TypeDoc workspace и запись в catalog,
   настройка TypeDoc, стартовые страницы API-сайта и workflow GitHub Pages. Репозиторий не коммитит
   и не публикует generated HTML.
3. **API-документация остаётся рядом с исходниками пакетов.** При будущем релизе на crates.io docs.rs
   соберёт Rustdoc из опубликованного крейта. TSDoc остаётся в TypeScript-исходниках и declaration
   output после появления сборки npm-пакетов, давая quick info в IDE без TypeDoc.
4. **Публикация — отдельное решение.** Пакеты не становятся публичными, release pipelines не
   добавляются. Rust `publish = false` и npm `private: true` остаются без изменений.

## Альтернативы

- **Оставить generated site.** Централизованный поиск удобен, но требует зависимостей и времени CI,
  дублируя docs.rs и документацию редактора.
- **Коммитить generated HTML.** Не нужен release workflow, но generated diff велик и сразу устаревает.
- **Удалить также API-комментарии.** Исходники стали бы проще, но docs.rs, declaration consumers и
  IDE quick info потеряли бы документацию.
- **Сразу добавить публикацию crates/npm.** Это смешало бы удаление инфраструктуры с release-политикой
  и устройством пакетов; такие изменения требуют отдельных issues.

## Последствия

- (+) Больше не нужно поддерживать TypeDoc, изолированную версию TypeScript, нативные зависимости
  Rustdoc CI и настройку Pages.
- (+) Двуязычные руководства и английские API-комментарии полезны без generated artifacts.
- (−) Централизованного поискового API-сайта у репозитория больше нет.
- (−) Документация docs.rs появится только для опубликованных крейтов; npm quick info зависит от
  сохранения TSDoc в declarations будущей сборкой пакетов.
