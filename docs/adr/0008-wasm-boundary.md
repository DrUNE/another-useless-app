# 0008. Граница WASM: порты реализуются в JS, артефакты не коммитятся

Статус: принято (2026-10-31). Дополняет [ADR-0002](0002-rust-core-wasm-for-web.md),
[ADR-0003](0003-ports-and-adapters.md) и [ADR-0006](0006-independent-builds.md).
Пункт 7 в части тестов моста заменён [ADR-0013](0013-wasm-boundary-tests-in-typescript.md).

## Контекст

По ADR-0002 web получает то же Rust-ядро, собранное в WASM. В WASM нет файловой системы и сокетов,
поэтому порты `Fs` и `Http` ядра ([ADR-0003](0003-ports-and-adapters.md)) должны быть реализованы
браузерными средствами: OPFS и `fetch`. Нужно решить, где живут эти реализации, как они попадают
в Rust и что делать с артефактами сборки.

## Решение

1. **Тонкая привязка.** Крейт `crates/core-wasm` (`wasm-bindgen`) только экспортирует use-cases
   ядра в JS и реализует порты `Fs`/`Http` поверх JS-объектов. Логики в нём нет.
2. **Порты передаются из JS при вызове.** `saveUrl(fs, http, url, path)` принимает объекты нужной формы.
   Их TS-типы (`WasmFs`, `WasmHttp`) **генерируются из Rust** через `typescript_custom_section`: контракт
   живёт рядом с кодом, который на него полагается, и TS-адаптеры проверяются компилятором.
3. **TS-мост.** `packages/core-wasm/src/bridge.ts` переводит порты `@app/platform` в узкие порты Rust.
   Пример: у TS-порта `writeBytes` не создаёт каталоги, а порт Rust `write` обязан, поэтому мост вызывает
   `mkdir`. Ядро не знает про TS-порты, а TS не знает про форму Rust-портов.
4. **Адаптеры веба на TS** (`packages/platform-web`: OPFS и `fetch`), а не на Rust. TS-порты нужны UI и
   без WASM, поэтому реализация одна и используется всеми.
5. **Артефакты не коммитятся.** `packages/core-wasm/pkg` генерируется командой `bun run build:wasm`
   (`wasm-bindgen --target web`) и лежит в `.gitignore`.
6. **Версии синхронны.** Крейт `wasm-bindgen` закреплён как `=0.2.x`; CLI обязан иметь ту же версию.
   В CI версия CLI берётся из `Cargo.lock`, чтобы её нельзя было забыть обновить в двух местах.
7. **Проверки по зависимости от артефактов.** Общий `bun run typecheck` не требует Rust и проверяет то,
   что не зависит от `pkg`. Код, импортирующий `pkg`, проверяется командой `bun run check:wasm`
   (сборка и `tsc`) в отдельной CI-проверке `wasm (build and test)`. Тесты моста под Node
   (`cargo test --target wasm32-unknown-unknown`) идут через `wasm-bindgen-test-runner`.

## Альтернативы

- **Адаптеры на Rust (`web-sys`).** Один язык на всё и нет TS-моста. Но привязки File System Access в
  `web-sys` нестабильны (требуют `--cfg web_sys_unstable_apis`), а TS-реализация портов всё равно
  нужна UI. Получили бы две реализации одного порта.
- **`wasm-pack`.** Удобная обёртка, но лишний слой над тем же `wasm-bindgen`. Прямой вызов CLI проще
  и прозрачнее, а для обучения важнее видеть, что происходит.
- **`--target bundler` с плагином для Vite.** Нужен плагин и неявная загрузка. `--target web` с явным
  `init()` работает в любом бандлере и даёт контроль над ленивой загрузкой и повторной попыткой.
- **Коммитить `pkg`.** Упрощает сборку web (не нужен Rust), но засоряет диффы бинарным артефактом
  и допускает рассинхрон с Rust-кодом.

## Последствия

- (+) Контракт между Rust и JS типизирован с обеих сторон, источник типов один (Rust).
- (+) Мост и адаптеры тестируются без браузера (Node); сквозной сценарий проверен в Chromium.
- (+) WASM-пакет небольшой: 77 КБ (release, без `wasm-opt`).
- (−) **Сборка web теперь требует Rust**, таргет `wasm32-unknown-unknown` и `wasm-bindgen-cli`.
  Это смягчает ADR-0006: «web не требует Rust» больше не верно. Остаётся верным, что web не требует Tauri.
- (−) **Один порт, разная семантика.** `Http` в браузере подчиняется CORS, нативный клиент нет: запрос
  к чужому источнику без `Access-Control-Allow-Origin` падает с `network: Failed to fetch`. OPFS — песочница
  браузера, а не файловая система пользователя, и пути не совпадают с нативными. Порт задаёт форму,
  а не гарантирует одинаковое поведение; различия нужно документировать и учитывать в UI.
- (−) Нужно вручную освобождать объекты, созданные в памяти WASM (`report.free()`): в JS нет деструкторов.
- (−) Появился третий тулчейн в CI (job `wasm`). Список обязательных проверок из ADR-0007
  нужно дополнить именем `wasm (build and test)`.
- Не проверено: Safari и Firefox. Поддержка `createWritable` в OPFS у браузеров различается.
