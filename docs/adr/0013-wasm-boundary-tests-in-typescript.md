# 0013. Тесты границы WASM на стороне TypeScript, без Node.js

Статус: принято (2026-10-31). Заменяет пункт 7 [ADR-0008](0008-wasm-boundary.md) (тесты моста через `wasm-bindgen-test-runner`) и часть
[ADR-0012](0012-reproducible-dev-environment.md) о Node.js в образе и в `doctor`.

## Контекст

[ADR-0012](0012-reproducible-dev-environment.md) выяснил: `bun run test:wasm` не работает без настоящего Node.js. Проект выбрал bun
вместо связки Node.js и pnpm, поэтому скрытая зависимость от Node.js ради одного инструмента противоречит цели. Стало нужно понять причину
и выбрать замену.

**Причина** (найдена по исходникам `wasm-bindgen-test` и подтверждена в контейнере без Node.js):

1. `wasm-bindgen-test-runner` запускает тесты командой `node` (имя зашито в коде).
2. Внутри тестов `detect()` (`crates/test/src/rt/detect.rs`) считает окружение браузером, если определено `globalThis.self`
   (кроме Deno, который проверяется отдельно). В Node `self` нет.
3. У bun `self` определён (`self === globalThis`, конструктор `Object`), `Deno` нет, поэтому bun распознаётся как браузер, создаётся
   браузерный форматтер и тест падает на `document` (`ReferenceError: document is not defined`).

Воспроизводится на минимальном крейте с одним тестом под `bun run`, если Node.js нигде не установлен. Если на машине есть Node.js
(например, от `fnm`), `bun run` может найти его, и тест пройдёт: **проверять «без Node.js» на машине с менеджером версий Node ненадёжно**,
арбитром служит только контейнер, где Node.js физически нет.

## Решение

Границу Rust↔JS тестируем с той стороны, с которой её вызывают: из TypeScript, на bun.

- `packages/core-wasm/src/wasm.test.ts` (vitest) грузит собранный `pkg/app_core_wasm_bg.wasm` через `initSync` и вызывает `saveUrl` так же, как
  `createCore`. Семь сценариев: успешная загрузка и запись, ошибка статуса без записи, `Error` из порта файлов, строка вместо `Error`,
  сбой запроса как сетевая ошибка, тело ответа не `Uint8Array`, ответ без числового статуса. Последние три раньше не проверялись.
- Тест требует собранного WASM, поэтому обычный `bun run test` его исключает (`--exclude`), а `bun run test:wasm` сначала собирает WASM.
  В CI это шаг job `wasm`.
- Удалены: `wasm-bindgen-test` и Rust-тесты привязки, `.cargo/config.toml` с раннером, Node.js в образе и проверка Node.js в `doctor`
  (вместе со статусом `warn`, которому больше нечего выражать).
- Тесты проверены мутациями: четыре намеренные поломки Rust-привязки (текст ошибки, описание ошибки порта, проверка статуса,
  размер в отчёте) каждая роняют минимум один тест.

## Альтернативы (каждая проверена экспериментом)

- **Оставить настоящий Node.js.** Надёжно, но тянет Node.js ради одного инструмента.
- **Шим `node`, который запускает bun с предзагрузкой `delete globalThis.self`.** Работает (3 теста проходят), но завязан на устройство `detect()`
  и неудобен на Windows.
- **Режим браузера** (`WASM_BINDGEN_USE_BROWSER`, headless Chromium и `chromedriver`). Работает и ближе к реальной среде WASM, но требует браузер и
  драйвер одной версии (сотни мегабайт в образе и CI).
- **Deno** (раннер поддерживает официально). Ещё один рантайм в проекте.
- **Исправить `detect()` в upstream:** добавить проверку глобала `Bun` рядом с `Deno`. Эта правка проверена на минимальном примере (тест проходит под bun
  без Node.js), текст обращения для `wasm-bindgen` подготовлен, **публикация пока не состоялась**. Если исправление примут, `wasm-bindgen-test` можно вернуть
  как дополнительный уровень проверок.

## Последствия

- (+) Node.js нигде не нужен: ни в образе, ни в `doctor`, ни в README. Один тулчейн для всех проверок.
- (+) Тест видит то, что видят пользователи пакета: сгенерированную обвязку и её поведение. Проверка занимает около секунды.
- (+) В процессе нашлась и исправлена настоящая ошибка: у `core-wasm` не было типов Node для тестового файла, `check:wasm` падал бы в CI
  (корневой `typecheck` этот пакет пропускает, потому что ему нужен собранный WASM).
- (−) `bun run test` без сборки WASM границу не проверяет: нужен `test:wasm` (в CI он есть).
- (−) Тесты идут на рантайме bun, а не в браузере, куда WASM попадает на самом деле. OPFS и `fetch` проверялись отдельно, в Chromium вручную;
  автоматизация в CI остаётся в #6.
- (−) Преобразования результатов `read` и `exists` в `JsFs` недостижимы через экспортируемый `saveUrl` (он вызывает только `http.get` и `fs.write`):
  они не тестировались ни раньше, ни теперь. Появятся тесты вместе с сценарием, который их использует.
- (−) Размер образа без Node.js измерен как 4,46 ГБ; в ADR-0012 указано 3,72 ГБ (замер с Node.js на прежних версиях базовых образов). Причину
  роста не выяснял: Node.js (около 120 МБ) её не объясняет.
- Не проверено: Windows и macOS как хосты для `test:wasm`.
